# 服务器部署说明(内网网页服务版)

> 目标形态:Linux 服务器 + Docker,内网免登录访问。
> 适用版本:2026-09 服务器化构建(源码见 `src/serve.py`、`Dockerfile`、`docker-compose.yml`)。

## 一、部署步骤

```bash
# 1. 上传项目到服务器(任选其一)
git clone <你的仓库地址> ai-news-search
# 或 scp -r ai-news-search/ user@server:/opt/

cd ai-news-search

# 2. 确认数据就位(data/ 内为文章 JSON 与 pdf/、img/ 子目录)
ls data | head

# 3. 构建并启动
docker compose up -d --build

# 4. 查看状态与日志
docker compose ps
docker compose logs -f
```

启动后内网访问:`http://<服务器IP>:8765/`

## 二、日常运维

| 操作 | 命令 |
|---|---|
| 新增/更新文章 | 把新 JSON 放入 `data/`(PDF 放 `data/pdf/`),**约 2 秒自动生效**,无需重启 |
| 修改标题/单位/分类/端口 | 编辑 `config.json`(端口改动需 `docker compose restart`) |
| 更新程序代码 | `git pull && docker compose up -d --build` |
| 停止/启动 | `docker compose stop` / `docker compose start` |
| 备份 | 备份 `data/` 与 `config.json` 即可(程序可随时重建) |

## 三、端口与反向代理

- 端口在 `config.json` 的 `server` 节修改,同时同步改 `docker-compose.yml` 的端口映射左侧。
- 如需走域名/统一入口,参考 `deploy/nginx.conf.example`(含 PDF 缓存与 HTTPS 接入提示)。

## 四、安全基线(内网免登录模型)

- 容器以非 root 用户运行,仅提供只读静态资源与查询接口,无写操作;
- `/data/` 路径穿越防护、安全响应头(nosniff/SAMEORIGIN/CSP)见 `docs/安全审查.md`;
- 请将 8765 端口(或反代后的站点)**仅发布在内网**,不要映射到公网;
- 如后续需要公网或跨部门访问,应先加认证层(如 nginx basic auth 或单位统一网关),再放开。

## 五、常见问题

- **端口被占用**:`端口 8765 已被占用` 报错为固定端口模式的设计(便于发现冲突),改 `config.json` 端口或停掉占用进程。
- **文章没显示**:确认 JSON 文件以 UTF-8 编码保存且含 `title`/`body` 字段;看日志 `docker compose logs`。
- **中文 PDF 打不开**:确认走浏览器或反代时未对路径二次转码;容器日志会记录 403/404。
